# 开源代码贡献准则

## 如何贡献

我们欢迎任何形式的贡献，包括但不限于：

1. 报告 Bug：通过 GitHub Issues 提交你发现的问题
2. 功能建议：通过 GitHub Issues 提出你希望添加的功能
3. 代码贡献：通过 Pull Request 提交代码改进
4. 词库贡献：添加新的词典文件（参见 [导入词典](./toBuildDict.md)）
5. 文档改进：改进 README 和其他文档

## 在开始做 PR 之前

1. 在 **GitHub Issues** 中讨论你的想法，确认这个改进符合项目需求
2. 如果相关 Issue 不存在，请创建一个新的 Issue 来描述问题、解决方案和相关细节
3. 在 Issue 中回复表明你将着手处理，避免重复工作
4. Fork 本仓库到你的 GitHub 账户

## 在 PR 过程中

1. 创建一个新的分支进行开发（不要直接在 master 上提交）
2. 尽早提交 Draft PR，方便其他开发者参与讨论和提供帮助
3. 确保代码遵循项目的代码风格（使用 `pnpm prettier` 格式化代码）
4. 如果添加新功能，请确保代码经过充分测试
5. 在 PR 描述中清晰说明你的改动和解决的问题
6. 保持 PR 专注于单一问题或功能，避免在一个 PR 中混合多个不相关的改动

## 提交 PR

1. 确保你的代码可以通过 `pnpm build` 构建
2. 推送你的分支到你的 Fork 仓库
3. 在 GitHub 上创建 Pull Request，目标分支为本仓库的 `master`
4. 在 PR 描述中引用相关的 Issue（例如：`Fixes #123`）
5. 等待维护者 Review，根据反馈进行修改

## 行为准则

1. 尊重所有贡献者，不论其技术水平、经验、性别、性取向、种族、宗教信仰或国籍
2. 保持开放的心态，愿意接受其他人的批评和建议，并根据反馈进行改进
3. 提交有价值的贡献，符合项目需求并遵守项目的开发规范和质量标准
4. 不要在 PR 或讨论中使用不礼貌或侮辱性的语言
5. 遵守代码行为准则，不要进行不道德或不法的行为，如抄袭、篡改他人代码、恶意破坏等
6. 保持话题与项目相关，尊重他人的意见和观点
7. 遵守相关法律法规和 GitHub 平台的规定

## 反馈

如有任何问题或建议，请随时在 GitHub Issues 中提出，我们将及时回复。

欢迎参与项目的讨论和开发，共同打造更加优秀的开源项目！

## 写在最后

不要害怕提出问题，不要害怕提出 PR，不要害怕提出建议！

每一个贡献都是有价值的，无论大小。我们相信开源社区的力量，期待你的参与！

## Contribution Guidelines (English)

## How to Contribute

We welcome all forms of contributions, including but not limited to:

1. Bug reports: Submit issues you find via GitHub Issues
2. Feature suggestions: Propose features you'd like to see via GitHub Issues
3. Code contributions: Submit code improvements via Pull Requests
4. Dictionary contributions: Add new dictionary files (see [Adding Dictionaries](./toBuildDict.md))
5. Documentation improvements: Improve README and other documentation

## Before Starting a PR

1. Discuss your idea in **GitHub Issues** to confirm it aligns with project needs
2. Create a new Issue if one doesn't exist to describe the problem, solution, and details
3. Comment on the Issue to indicate you'll work on it, avoiding duplicate effort
4. Fork this repository to your GitHub account

## During the PR Process

1. Create a new branch for development (don't commit directly to master)
2. Submit a Draft PR early for discussion and help from other developers
3. Ensure code follows project style (use `pnpm prettier` to format)
4. If adding new features, ensure code is thoroughly tested
5. Clearly describe your changes and the problem solved in the PR description
6. Keep PRs focused on a single issue or feature

## Submitting a PR

1. Ensure your code builds with `pnpm build`
2. Push your branch to your forked repository
3. Create a Pull Request on GitHub targeting this repository's `master` branch
4. Reference related Issues in the PR description (e.g., `Fixes #123`)
5. Wait for maintainer review and address feedback

## Code of Conduct

1. Respect all contributors regardless of technical level, experience, gender, orientation, race, religion, or nationality
2. Be open to criticism and suggestions, improving based on feedback
3. Submit valuable contributions that meet project standards
4. Don't use disrespectful or insulting language in PRs or discussions
5. Follow ethical behavior; no plagiarism, tampering, or malicious actions
6. Keep discussions project-related and respect others' opinions
7. Comply with laws and GitHub platform regulations

## Feedback

If you have any questions or suggestions, feel free to raise them in GitHub Issues. We'll respond promptly.

Welcome to project discussions and development. Let's build an excellent open source project together!

## Final Words

Don't be afraid to ask questions, submit PRs, or make suggestions!

Every contribution is valuable, no matter how small. We believe in the power of the open source community and look forward to your participation!
